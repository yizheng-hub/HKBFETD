# HKBFETD

Hong Kong Building Function and Energy Typology Dataset for Urban Building Energy Modeling (UBEM).

## Project Structure

- `src/`: pipeline scripts (`1` to `10`) and shared config/utils
- `data/`: input datasets (LandsD, BDBIAR, OSM/Overture, OZP, etc.)
- `intermediate_files/`: intermediate artifacts generated by the pipeline
- `output/`: final and step-wise outputs (CSV/GeoJSON/maps/figures)
- `log/`: runtime logs for each step script (TXT)
- `ctl/`: control files (taxonomy, keyword rules, step mappings, prompts)

## v2 reproduction

The v2 repair preserves the public v1/v1.1 files. The single final publication
folder is `output/zenodo_upload_v2/`; older `output/v2` candidates are not release
inputs. This repository contains the SD building classification project only.

The public GeoJSON uses RFC 7946 WGS84 longitude/latitude (EPSG:4326),
with nine decimal places and no legacy `crs` member. GeoParquet retains
EPSG:2326 metric geometry. Attributes and identifiers agree across CSV,
GeoJSON and GeoParquet; areas remain in square metres and heights in metres.
Use projected geometry for area calculations.

The corrected V2 classification replay keeps the published method fixed at the
original sequence: keyword rules, frozen LLM/VLM checkpoints, the original nine
machine-learning features, and the original Step 10 public-label
standardization. The replay binds the verified physical-attribute table, the
GFA-rule withdrawal list, explicit non-building scope, 79 original-prompt review
results, the frozen VLM suggestions and their reuse audit. The 427 cached prompts
whose storey value changed are diagnostic checks only. The replay does not read
web-derived function evidence and does not make external AI requests.

Activate `HKbuilding`, extract `reproduction_inputs_complete.zip` from the same V2
release, and run its checksummed manifest through the formal replay entry:

```powershell
python src/replay_original_v2.py `
  --inputs-manifest reproduction_inputs/original_method_v2/manifest.json `
  --output-dir output/v2_original_replay
```

Use `--check-only` to verify all inputs and frozen source hashes without running
classification. Use `--resume` to reuse only output files whose source, input,
upstream and output hashes still match. The classification table consumed by
the release builder is
`output/v2_original_replay/ml/step10_original_method_standardized.csv`; raw
Step 9 output is not a public classification table.

The optional physical-source rebuild remains separate from the formal
classification replay. Extract
`physical_source_inputs_20261025.zip` from the reproduction archive into this
checkout, then run:

```powershell

```

To continue an interrupted physical-source rebuild, use
`python src/run_pipeline.py --resume --through 2 --input-bundle`.
Completed stages are reused only when source, inputs, upstream results and output

restore that environment or run a full rebuild. Logs are in `log/v2/runner_step_N.txt`.
`--run-root D:\HKBFETD-replay` puts generated results in a separate directory;
source inputs continue to be read from this checkout. The corrected publication
classification must use `replay_original_v2.py`; the later experimental stages
in `run_pipeline.py` are not the corrected V2 release method.

Required binary inputs are not in Git. Use
`reproduction/reproduction_inputs_complete.zip` from the final release. It
contains:

- the frozen raw/source bundle used by physical stages 1–2;
- the successful runtime versions and package lock;

The source-evidence archive records the adopted physical facts and scope limits.
Live OSM/CSDI extracts, terrain samples, and external model calls cannot be

Generic residential tags do not determine public/private housing tenure;

## Physical attributes and uncertainty

`Height_m` is **structural component height**, calculated as top minus base
elevation. Towers and podiums remain separate structures. Source top elements
are not guaranteed to exclude masts or follow architectural-height conventions.
CSDI Building source elevations are supplemented from a frozen
official bulk download, matched by unique `BuildingCSUID`, compatible
structure type and valid footprint IoU >=0.95. Local geometry is retained and
the distributor's derived `height_m` is ignored. The original footprint table's
`T` includes open-sided/temporary structures; CSDI's finer type is retained.

`Ground_To_Top_Height_m` separately records datum top minus point DTM, or OSM
reported height with an unverified reference. OSM height is adopted only when its
source object is uniquely scoped to that component; shared or unknown object scope
remains raw candidate evidence. These are not substitutes for a missing component
base. An ICC tower starting on a podium therefore has a different component and
ground-to-top height. Source/quality/reference fields
distinguish these meanings. Conflicts in comparable sources are withheld;
different-reference discrepancies are flagged. Missing heights are not filled
with 15 m. Original dimensions remain unchanged in raw fields.

`landmark_building_reference_attributes.csv`, when present in the release,
provides separately scoped whole-building reference facts for Bank of China
Tower and ICC. It records documented body/architectural heights and CTBUH
above-ground main-floor counts, with explicit definitions and sources. These
facts remain usable even when their conversion to a mapped component's vertical
extent is unresolved. They do not overwrite component elevations or supply
component GFA/model inputs. See `LANDMARK_REFERENCE_README_zh.txt` for the join
keys and source-to-component limits.

In the final V2 table, Bank of China Tower (Building ID 181189) uses the matched
component height 303.3 m and an unknown component floor count. ICC (192326) uses
the matched tower-component height 460.6 m and an unknown component floor count.
Their owner/CTBUH whole-building heights and 65/70/72 or 103/108/118 floor claims
remain separately scoped evidence because no complete component-level vertical
crosswalk resolves those definitions.

The source provider is [LandsD CSDI Building](https://portal.csdi.gov.hk/csdi-webpage/metadata/landsd_rcd_1637211194312_35158/html).
The active snapshot is the official 2026-10-20 bulk release, with 342,233
components. Download URL and raw/GeoParquet SHA256 are recorded in
`csdi_official_20261020.metadata.json`. `DateCreate` and `DateStamp` are retained
as record dates, not construction or survey dates. The earlier distributor
snapshot is preserved locally in the previous release's input archive.
The explicit acquisition command is `python src/fetch_csdi_buildings.py --bulk
--output data/sources/csdi_official_20261020.parquet`; replay uses the frozen
input bundle and does not contact the provider. Source reports do not constitute
independent whole-stock validation.
The 2025-02-06 building inventory is retained for an exact v1.1 comparison;
new/different-source IDs do not silently expand the stock to the current date.

Reported storeys and the optional `height / 3 m` proxy are separate fields.
The proxy rounds to the nearest integer, with half ties upward after normalizing
the ratio to nine decimal places. It does not enter reported storeys or GFA. GFA is a scoped registered
value, documented component GFA, or an explicitly marked footprint-times-reported-storeys approximation.
Shared permits are not allocated in full to each constituent building.
Source storey differences over max(1 storey, 10%) remain unresolved unless an
explicit same-component physical-storey document reconciles them. The reviewed
facts in `ctl/building_attribute_evidence.csv` preserve source URLs, dates,
attribute-specific units/scopes and adoption decisions. Central Plaza's 75
and Prosperity Millennia Plaza's 32 are supported tower counts. Langham Place's
59 reported levels have an unresolved physical-storey reference and do not
supply the primary count or floorplate proxy. Competing labels and whole-development claims remain
separate. Mechanical/refuge levels are included where the document says so;
reported storeys do not imply occupied office-floor counts. A component
height/storey ratio outside 1–20 m also withholds the fused storeys and related
proxy GFA because their scopes may differ; reported raw counts remain available.
An otherwise publishable pair with at least two reported storeys and less than
2 m of component span per storey is also quarantined until its vertical scope
is reconciled. Both primary dimensions and dependent proxy GFA remain unknown;
this screen does not identify which raw source value is wrong.
These are conservative review rules, not measured error bounds.
Explicit unresolved documentary height-reference conflicts withhold the primary
height and optional height-derived storeys; the pre-review height and raw
elevations remain available. A conflicting whole-tower height is not inserted
as a component height.
Owner-documented component GFA is retained separately from registration. The
best-available area prefers registration, then documented component GFA, then
the uniform-floorplate proxy. Rentable, saleable and unit internal areas are not
relabelled GFA. Documented approximate areas retain that qualification in their
source facts; exact unit conversion does not imply extra measurement precision.

`aggregate_cached_housing.py SNAPSHOT_DIRECTORY BUILDING_PARQUET` replays the
supplementary Housing Authority evidence from checksummed normalized snapshots
in `attribute_source_evidence.zip`. It works offline and does not change primary
classification, heights, storeys or GFA. Its block-name matches remain candidates;
estate coordinates do not establish a component match. District-level download
failures remain incomplete, rather than being interpreted as empty stock.
OSM whole-building storeys may include a podium. They donate to component
storeys only when the component base is within 3 m of sampled terrain and the raw
source object is uniquely scoped to that component. Shared or unknown object scope
remains candidate evidence and cannot supply primary storeys. The public fields
`OSM_Dimension_Scope_QA`, `OSM_Dimension_Raw_Matched_Component_Count` and
`OSM_Dimension_Candidate_Evidence` retain this scope and the raw reported values.
Other OSM reports remain separate and do not invalidate official component counts.

Building-footprint inventories also contain non-building structures. Fourteen
components were geographically identified as bridge pylons, including eight
meeting the small-footprint/tall review threshold,
using Highways Department factsheets, with stable IDs/coordinates/evidence in
`ctl/verified_structure_evidence.csv`. Explicit OSM infrastructure polygons must
match a unique footprint with IoU >=0.8. Generic tower tags do not exclude pagodas,
observation towers or pumping-station buildings. Identified infrastructure is
marked `Energy_Assessment_Scope=excluded_nonbuilding_structure`; its structural
height and original attributes remain, while building storeys/GFA proxies are
not applicable. Bridge pylons do not constitute unexplained building-height errors.
Unclassified structures over 100 m tall with footprints below 150 m2 do not
receive a model-only building function without occupied-building evidence.

Footprint area describes each structural record, not disjoint land coverage.
Tower/podium footprints may overlap or coincide. Use a geometry union for ground
coverage; do not interpret their summed footprints as net land area.

Function evidence, classifier probabilities and use-area fractions are separate.
POI counts and model probabilities do not become area shares. V2 reuses the
original rule definitions, keyword file, LLM/VLM decisions, nine-feature model
and public-label mapping from commit `de8b46b`; later web research about building
use is retained only as audit material and is not an input to classification.
Changes in the corrected V2 classification can therefore arise only from the
explicit GFA-evidence withdrawal, the 79 original-prompt candidates without a
legacy cache entry, the frozen VLM propagation decisions, or retraining the
original model with corrected physical inputs. Another 427 cached prompts whose
storey input changed were reviewed as diagnostics and were not allowed to
replace the established function classification. Missing or conflicting physical
facts remain null in the published fields; the original model's internal 15 m
imputation is not written back as a building height.

## Optional AI review and image recovery

This optional legacy workflow is not an input to the corrected V2.0 release.
The corrected release replays only the frozen, checksummed checkpoints in its
reproduction archive.

Text and vision review are targeted at functional or footprint ambiguities.
Neither is allowed to invent height, storeys, GFA or use percentages. API keys
must come from `HKBFETD_API_KEY` / `HKBFETD_VISION_API_KEY` environment variables;
never place credentials in source files. Provider URL and model settings also
accept `HKBFETD_*` environment variables, as listed in `src/config.py`.

Steps 4 and 6 default to offline queues and input-matched cache reuse. An optional
`data/sources/native_function_classifier_checkpoint.json` and matching
`native_function_policy_clarification.txt` replay recorded interactive native
reviews without a model call. The checkpoint retains original requests, public
packets, responses and root review evidence; separately bound source rows,
geometry and policy must match. Missing original context stays explicitly
missing. Only complete, individually approved labels can change classification;
reviewed abstentions and stale evidence remain distinct. Native results are
separate from provider API caches and from ML training labels.
Changed requests replace earlier responses only through an explicit, hash-bound
supersession; the earlier packets remain intact. Rejected labels are recorded as
nonadoptions, and original response bytes are retained separately from root corrections.

Explicit commands for requesting new evidence are:

```powershell
python src/4.llm_verification.py --refresh --limit 100
python src/5.evaluation_and_merge.py
$env:HKBFETD_RUN_ROOT = (Resolve-Path reproduction_run).Path
python src/6.geometry_ai_arbitration.py --images --scope-id-file review_scope_ids.csv --image-limit 100
```

The image scope CSV contains `fragment_id` or `building_id`; alternatively,
`--pair-whitelist` requires `fragment_id,host_id,Context_SHA256`. Images are
generated only inside the isolated run root. Each pair binds its geometries,
function context, imagery provider, acquisition time and image hashes; both
views use the same basemap capture. Image generation makes no model API call.
The separate `--refresh --limit 100` option requests paid-provider decisions
only when explicitly enabled with a configured key.

After reviewed changes, regenerate Steps 7–10. New decisions are saved atomically
with prompt/model/input and image hashes. A successful fingerprinted checkpoint
can survive loss of its temporary image path. Every surviving image is still checked by content,
including when the other image has been lost. Old caches without these hashes
remain historical evidence and are not silently treated as fresh v2 verification.
Step 6 recovers the 200 archived images from `Validation_Materials.zip` into the
run root and exports their archive/payload hashes. These historical pixels have
unverified geometry context and cannot satisfy a new scoped image review.
Other deleted images require reacquisition and may represent different imagery
dates. Existing user image directories are not modified by recovery.

## V2.0 release deliverables

The corrected publication package is built only by `src/build_v2_release.py` and
is written to `output/zenodo_upload_v2/`. The builder accepts explicit files,
validates CSV/GeoParquet/GeoJSON IDs and fields, requires passing machine-readable
validation reports, and writes both a package manifest and SHA-256 checksums. It
does not scan older `output/v2` candidates.

The package contains:

- `HKBFETD_v2.csv`, `HKBFETD_v2.parquet`, and `HKBFETD_v2.geojson`;
- `schema.json` and a Chinese release README;
- the retrained original-method model and metrics;
- physical, classification-integrity, and V1.1-to-V2 comparison reports;
- a checksummed frozen replay-input archive and source snapshot;
- source-scope and landmark evidence needed to interpret adopted and withheld
  dimensions.

All 341,153 stock records are covered by automatic source, range, formula,
cross-format, and classification-integrity checks. Physical facts that cannot be
mapped reliably to a tower, podium, or whole-building component remain null with
source and quality fields. This is a declared unknown, not a replacement value.
The release validation establishes reproducibility and consistency with the
cited sources; it does not claim that every unknown building attribute has been
independently measured in the field.

The V1.1 comparison is ID-exact. Every V1.1 row whose classification source
contains `Keyword` keeps its main class. Main-class changes outside that set are
reported separately for non-building scope, withdrawn GFA-dependent rules,
frozen VLM decisions, and retraining of the original nine-feature model. Later
web research about building use is not a classifier input.
